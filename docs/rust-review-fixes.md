# 正确性与性能改进

本文记录 2026-09-22 开发审查中的改进及测量，当前实现的格式与验证结果分别见 [数据格式](format.md)和[验证记录](verification.md)。

## 已实现的校验与算法

| 主题 | 实现行为 |
|---|---|
| 合并类型一致性 | 发布前按目标 schema 批量规范化检查候选记录，值表达一致后提交 |
| 删列与记录合并 | 对另一侧新行在已删除列中的值进行冲突校验，覆盖两个合并方向 |
| 新字段默认值 | 预计算投影计划，由适配器取得常量默认值，保留已有字段的显式 NULL |
| 同名 SQL 对象 | 区分索引头、表名、函数调用和列引用，按列身份处理改名 |
| 工作副本预览 | dirty 主键分页、约 8 MiB 批读、有限预览，提交与恢复逐批消费 |
| 合并基点 | 可达位传播和父边缓存，按唯一最佳共同祖先处理三方合并 |
| 树差异 | 有序任务栈按优先级展开，在解码前跳过共享子树，流式产生差异 |

类型转换需要调整候选表达时，先在分支中显式对齐值或类型，再完成合并。自定义 resolve 值经过数据库规范化，发布前再次校验。SQL 定义比较围绕可识别的列引用和已有依赖进行，覆盖保留字、列与表/索引/函数同名等情况。

## 测量口径与结果

对 10,000 行、每行 8,192 字节文本的专用数据，使用 debug CLI 运行 status --limit 1：1,000 条脏记录时峰值 RSS 从 40.67 MiB 降为 25.55 MiB；10,000 条时从 184.30 MiB 降为 33.56 MiB。后者耗时为 5.457 秒与 5.393 秒，属于相近水平。RSS 记录直接 CLI 进程，8 MiB 为记录批次预算，进程还包含驱动、索引和 SQLite 缓存等内存。

核心计数实验中，800 次线性提交且相同 HEAD 的 merge_base 对象读取由 322,000 次降为 1 次；1,001 个共享祖先和两个分支提交的场景读取至多 1,003 个对象；4,000 条记录新增根端点键的差异读取由 8,003 次降为 2 次。完整差异计数仍按实际变化范围遍历，结构合并保存相应候选和冲突状态。

## 工程实现与验证

后端错误保留 source 链，异步响应在阻塞线程中有界编码并复用 JSON。变更流和合并校验分别位于 [changes.rs](../crates/app/src/changes.rs) 与 [merge_working.rs](../crates/app/src/merge_working.rs)。当日审查回归实际执行 50 项测试并通过，覆盖真实 PostGIS、错误重现、预览预算、历史恢复、树差异与来源链；格式、Clippy 和 Rust 1.88 全目标编译检查通过。该节为当日开发记录，本轮结果见当前验证文档。

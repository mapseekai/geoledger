# Rust 审查问题修复与验证

> 本文保留改名前的历史命令、路径与实测结果；当前项目名为 `geoledger`，命令为 `gl`，配置使用 `GL_*`。重命名与兼容边界见 [重命名说明](rename-to-geoledger.md)。

2026-09-22。对应上一轮确认的四项正确性缺陷和三项性能问题，并包含错误处理、异步编码和模块拆分改进。没有改变 `record/v1`、树节点、提交、schema/v2 或仓库状态的编码格式。

| 问题 | 修复后的行为 |
|---|---|
| 类型变化合并导致仓库/数据库不一致 | 发布合并前按目标 schema 批量规范化检查候选记录；若值表达会改变，返回 conflict，不生成不一致提交 |
| 删列与新行合并静默丢值 | 另一侧新行在已删除列中的非空值也触发冲突；检查两个合并方向 |
| 默认非空字段与旧结构新行不能合并 | 预计算投影计划，由适配器一次取得缺失字段的常量默认值；显式 NULL 保持不变 |
| 字段与表/索引/函数同名导致伪冲突 | 定义比较保留索引头、表名、函数调用与限定名称，仅对可识别的列引用进行改名；恢复同样经过验证 |
| 工作副本分页累计全部 before/after | dirty 主键 keyset 分页、约 8 MiB 记录批读、有限预览；普通提交/恢复逐批消费，不再保留完整变更列表 |
| 合并基点平方级重复读取 | 可达位传播与父边缓存；每个提交只解码一次，共同祖先通过直接父边排除旧祖先 |
| 根旋转时完整物化两侧子树 | 有序任务栈按 treap 优先级展开，在解码前跳过共享子树；流式产生差异 |

自动合并采用保守规则：即便只是目标类型规范文本不同，也要求先在分支上显式对齐值/类型，避免把任何隐式变化藏在数据库写入阶段。例如 `text → varchar(3)` 与另一分支的 `abcdef` 合并会报 conflict，而不会再出现仓库存 `abcdef`、数据库存 `abc` 的情况。显式字段转换命令仍遵循此前的 PostgreSQL cast 行为；旧值仍可从历史恢复。`resolve` 对用户明确选择的值进行规范化，合并完成前再次验证最终候选。

结构依赖比较仍采取保守拒绝策略，不是通用 SQL AST 迁移器；没有扩大任意索引/约束修改的支持范围。新回归覆盖字段与表名、索引名、函数名相同，以及向旧版本恢复。

`status` 和 `diff` 的预览同时受 limit 和约 8 MiB 载荷预算约束，单条超大记录可超过批大小。`total` 仍精确计数，`truncated` 按实际返回数计算；结构漂移时继续用 `record_counts_complete=false` 表示记录计数不完整。这不是客户端游标分页接口。

dirty 的字节序 keyset 查询使用新增的 `_spatial_version.dirty_pk_c_v1` 索引。新建跟踪库直接创建；已有跟踪库首次使用时在事务内补建，使用全局初始化锁协调并发。只增加索引，不修改行数据或格式版本；跟踪表所有者需要具备建索引权限。触发器、表锁及 journal/marker 提交顺序保留。

错误类型新增通用后端来源包装，SQLite/PostgreSQL 原始错误可沿 `source()` 追踪，核心不依赖数据库 crate。主要任务执行错误保留 JoinError。异步接口通过阻塞工作线程中的有界 writer 编码一次，直接复用 JSON；编码期间继续持有执行槽位。Application 的变更流和合并验证分别移入 `changes.rs`、`merge_working.rs`。

## 实测对比

在本地 `spatial_version_test` 新建独立测试表，10,000 行，每行文本 8,192 字节，使用 debug CLI、macOS `/usr/bin/time -l`，分别开启独立进程运行 `status --limit 1`。前后采用同一复现脚本；以下为单次测量，不是吞吐量统计或空间大表保证。

| 脏记录数 | 返回条数 | 修复前峰值 RSS | 修复后峰值 RSS |
|---:|---:|---:|---:|
| 1,000 | 1 | 40.67 MiB | 25.55 MiB |
| 10,000 | 1 | 184.30 MiB | 33.56 MiB |

10,000 条时内存降低约 82%。墙钟时间从 5.457 s 到 5.393 s，视为基本持平，不据此宣称吞吐量提升。索引、驱动缓冲、单条记录、SQLite 缓存仍会占用额外内存，8 MiB 不是进程总内存上限。

核心库 release 计数实验：

- 800 次线性提交、相同 HEAD 的 merge_base：对象读取从 322,000 次变为 1 次。
- 非相同 HEAD 的规模回归：两个分支共享 1,001 个祖先，加两个分支提交，只读取至多 1,003 个对象；criss-cross 的多个最佳基点仍拒绝。
- 4,000 条记录中新增成为根的端点键：树差异对象读取从 8,003 次变为 2 次。
- 另有位于键范围内部的新根插入/删除测试，两个方向均限制读取少于 150 个节点；任意形状的差异还与参考 BTreeMap 逐项比较。

这些是针对所修瓶颈的规模测试，不能理解为所有合并或 diff 都只读取一两个对象。完整差异统计仍需要访问实际变化的全部节点；结构合并仍可能保留候选键和冲突记录。

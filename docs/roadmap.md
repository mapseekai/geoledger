# 后续实现顺序

## P0：可靠性，不先扩功能

恢复协议故障注入（数据库提交前后、SQLite 提交失败、进程退出、磁盘满）、full working-copy audit、备份/恢复检测、完整数据库权限测试、触发器绕过检测、更多约束组合测试。完善安装与迁移格式版本，明确默认值、序列、时间类型和扩展 geometry 类型的兼容矩阵。

## P1：性能和接口

已完成 48 万要素基线、1 万条变更、dirty 批读、SQL 批写、压缩上下文/语句复用和缓存优化。后续：百万要素及全量编辑基线、COPY、完全流式 diff/merge、游标分页、导入进度与取消、对象批编码、GC / 可达性清理、缓存可配置与冷/热多轮测量。验证读服务与写服务的锁竞争。

本轮实测的优先剩余项：整表结构差异仍需遍历全部树节点，483,268 条的历史 diff 精确计数用时约 257 秒；跨结构回填约 270–366 秒。需要评估对象索引与大载荷的存储布局、树遍历分页/缓存及保留触发器的 COPY 回填，不能仅扩大超时。

gRPC 从 JsonReply 逐步升级为明确的版本化响应与 Record / Change / Conflict 消息。增加 API 幂等键、请求追踪、授权范围和 TLS 部署样例。注意 commit 重试不能产生意外重复提交。

## P2：模型与数据适配

已完成稳定字段 ID、v2 迁移及新增/删除/改名/改类型，两种入口共用恢复协议。后续完善结构冲突交互解决、避免结构变化整表重编码的 legend/列 ID 记录布局，以及约束/默认值迁移。复合主键、identity、外键等需逐项定义语义。GeoPackage 可实现同一事务接口；GeoParquet 更适合文件快照/变化集，应增加能力声明，不强行伪装实时 dirty 表。栅格 / 点云设计独立分块对象、元数据、块级 diff，并复用提交图与引用。

## P3：协作与产品化

多工作副本/多用户分支隔离、对象传输、远程 refs CAS、clone/push/pull、服务鉴权和租户隔离、空间范围历史查询、交互冲突地图。几何顶点/拓扑语义合并作为独立策略，不默认开启。

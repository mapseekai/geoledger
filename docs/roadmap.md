# GeoLedger 开发计划

当前可用能力见 [README](../README.md)，本页列出后续开发与验证方向。

## P0 可靠性与验证

扩展 journal / marker 故障注入矩阵，覆盖数据库提交前后、SQLite 提交异常、进程退出和磁盘容量。完善工作副本全表核对、备份恢复检测、数据库权限及触发器完整性测试。维护当前格式的初始化流程和自动化回归。

## P1 性能与接口

在已有 48 万要素和 1 万条增量基线上，增加百万要素、全量编辑、冷/热缓存和多轮测量。评估 COPY 回填、对象批编码、树遍历缓存、结构历史差异、进度与取消、游标分页、缓存参数和对象回收。

进一步研究结构变更的整表扫描、历史差异精确计数及对象库增长下的访问成本，分别记录耗时、内存、磁盘和并发锁表现。接口方向包括类型化响应、请求追踪、幂等键、授权范围与 TLS 部署示例。

## P2 数据模型与适配器

在稳定字段 ID 和字段增删改类型的基础上，完善结构冲突交互、列身份记录布局及约束/默认值演进。逐项定义复合主键、identity 和外键语义。GeoPackage、GeoParquet、栅格与点云分别设计编码、分块、变化发现及事务恢复能力，并复用提交图与引用模型。

## P3 协作与产品化

扩展多工作副本和用户分支隔离、对象传输、远程引用更新、clone/push/pull、租户与授权隔离、空间范围历史查询和交互冲突地图。几何顶点与拓扑合并作为独立策略研究，并配置明确的输入条件及验证方法。

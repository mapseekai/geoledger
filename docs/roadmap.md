# 后续实现顺序

## P0：可靠性，不先扩功能

恢复协议故障注入（数据库提交前后、SQLite 提交失败、进程退出、磁盘满）、full working-copy audit、备份/恢复检测、完整数据库权限测试、触发器绕过检测、更多约束组合测试。完善安装与迁移格式版本，明确默认值、序列、时间类型和扩展 geometry 类型的兼容矩阵。

## P1：性能和接口

百万要素基线、10/100/10000 要素变更基线、批量读取 dirty 记录、SQL 批写 / COPY、流式 diff、游标分页、基于数据库执行结果的导入进度、取消与超时、对象批编码、GC / 可达性清理、压缩与缓存测量。验证读服务与写服务的锁竞争。

gRPC 从 JsonReply 逐步升级为明确的版本化响应与 Record / Change / Conflict 消息。增加 API 幂等键、请求追踪、授权范围和 TLS 部署样例。注意 commit 重试不能产生意外重复提交。

## P2：模型与数据适配

稳定字段 ID 和 schema 迁移；复合主键、identity、外键等需逐项定义语义。GeoPackage 可实现同一事务接口；GeoParquet 更适合文件快照/变化集，应增加能力声明，不强行伪装实时 dirty 表。栅格 / 点云设计独立分块对象、元数据、块级 diff，并复用提交图与引用。

## P3：协作与产品化

多工作副本/多用户分支隔离、对象传输、远程 refs CAS、clone/push/pull、服务鉴权和租户隔离、空间范围历史查询、交互冲突地图。几何顶点/拓扑语义合并作为独立策略，不默认开启。

# 大数据验证记录

本文记录 **2026-09-22 的开发性能基线**，保留当时测量的输入规模、耗时和资源口径。当前格式的功能回归见 [验证记录](verification.md)。性能数值用于对应样本和测试场景的比较。

## 环境与数据

macOS arm64，Rust 1.92.0 release 构建，Docker 内 PostgreSQL 17.7 / PostGIS 3.6.1，GDAL 3.12.2。多面样本为 9,384 个要素、4,345,620 个顶点，MultiPolygon / SRID 4326，输入 133,151,432 字节；三维多线样本为 483,268 个要素、23,040,506 个顶点，MultiLineStringZ / SRID 6663，输入 1,967,816,569 字节。

按数据库记录数、主键唯一数、SRID 和维数核对导入。几何保持输入表达；多面样本中 ST_IsValid 检测到 1,477 个无效几何，按原值参与测试。版本操作使用专用测试表。

## 普通数据操作

三维多线样本采用 900 秒单条 SQL 超时，两轮均处理 10,000 条属性更新和 10 条保留 Z 的几何平移。各版本操作通过 CLI → Application → PostGIS 执行。

| 操作 | 优化前 | 优化后 |
|---|---:|---:|
| 初始版本导入 | 123.575 秒 | 71.190 秒 |
| 检测 10,000 条增量，输出 1 条 | 37.496 秒 | 2.281 秒 |
| 提交 10,000 条增量 | 119.086 秒 | 22.799 秒 |
| 切回 main | 40.410 秒 | 6.857 秒 |
| 切回编辑分支 | 41.204 秒 | 5.672 秒 |
| 再切回 main | 39.246 秒 | 4.448 秒 |
| 快进合并 | 28.912 秒 | 2.985 秒 |
| revert | 53.211 秒 | 13.017 秒 |
| fsck | 498.086 秒 | 63.148 秒 |

切换、合并和 revert 后按主键排序计算全表行 JSON 摘要，并比较记录数，结果均符合预期。优化采用 dirty 批读、参数化批写、schema 写入复用、压缩上下文、预编译 SQL 和 SQLite 缓存。两轮分别使用独立仓库，结构对象与历史对象集合各有其范围。

## 资源与结构操作

初始导入 CLI 峰值 RSS 从 29.02 MiB 变为 110.91 MiB，增量提交从 109.91 MiB 变为 455.86 MiB，优化后的切换与合并约为 501–506 MiB。RSS 口径为 macOS time 测量的直接 CLI 进程，包含映射页；数据库、Docker VM 和系统缓存属于进程外资源。优化后的初始仓库为 1,076,957,184 字节。

483,268 行的首次新增字段提交耗时 471.076 秒。结构扫描随后采用文件型临时对象表和按哈希排序写入；新增字段的另一轮提交为 215.722 秒。两轮列名、历史库大小和缓存状态存在差异，分别保留为对应条件下的测量值。

| 结构验证场景 | 耗时 / 结果 |
|---|---|
| 字段改名 | 179.996 秒 |
| 字段修改类型 | 125.078 秒，100 条文本值转换为 integer 后均为 42 |
| 删除字段 | 137.522 秒，全表摘要恢复为初始基线 |
| 恢复含字段的历史提交 | 277.136 秒，字段及原值恢复 |
| 恢复原始结构 | 270.106 秒；后续较大历史库上的一次恢复为 365.728 秒 |
| 外部 DDL 状态检查 | 0.050 秒，返回结构变化和完整扫描标记 |
| 历史 diff，limit=1 | 257.190 秒，total=483268，truncated=true，峰值 RSS 260.78 MiB |
| 最终 fsck | 4,109,530 个对象，ok=true，452.587 秒，峰值 RSS 307.45 MiB |

最终仓库文件合计 4,296,130,560 字节，约 4.00 GiB。主分支回到结构变更前的提交，工作副本干净，字段操作历史可通过对象 ID 或 reflog 查询。结构全量扫描、精确差异统计和历史对象保留构成相应的计算、I/O 与空间成本。

验证还覆盖 120 秒超时后的回滚一致性、900 秒配置完成导入，以及扫描中断后 HEAD、字段和工作副本状态保持一致。测量采用本机顺序执行和当时缓存条件，范围为上述样本、单机 CLI、快进合并及字段操作；进一步的规模、并发和故障矩阵安排在 [开发计划](roadmap.md)。

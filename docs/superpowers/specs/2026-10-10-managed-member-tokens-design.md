# 成员个人令牌管理设计

状态：已实施并通过本地验收；生产部署需使用全新格式 12 数据库。

## 用户目标

平台管理员在控制台为成员签发个人访问令牌。明文仅在成功签发的响应中返回一次，用户自行保存。丢失后撤销旧令牌、签发新令牌，不提供找回明文。项目角色继续独立管理。

## 权限和范围

只有配置在 GL_ADMIN_SUBJECTS 中的平台管理员可以列举、签发、撤销和重新签发受管令牌。项目所有者没有签发身份凭据的权限，避免冒用其他项目成员。Info 返回调用者是否为平台管理员及是否支持受管令牌，界面据此显示独立的“成员令牌”管理入口；后端每次操作仍检查权限。

第一版服务于本地令牌认证模式。JWT/JWKS 模式继续由外部身份提供方签发，关闭本地签发功能。已有 tokens.json 保留为运维管理的凭据来源，控制台明确不管理这些文件凭据；禁止为配置的平台管理员身份签发受管令牌，管理员恢复依靠运维凭据。

## 界面与操作

- 签发：填写成员身份、用途标签和到期时间（默认 90 天、必须晚于当前时间），确认后展示一次明文，可复制；关闭提示必须确认已保存。取消或离开页面后不可再次查询明文。
- 列表：显示令牌 ID、成员身份、标签、签发人、创建时间、到期时间和状态，不返回明文或摘要。按令牌 ID 分页。
- 撤销：显示身份和标签供确认，成功后旧令牌不再通过后续请求的认证；重复撤销成功。
- 重新签发：针对单个旧令牌，在同一事务中撤销旧令牌并生成同一身份的新令牌，其他令牌保持原状态。失败时整个事务回滚。
- 项目权限页继续负责 subject 与角色的映射，并提示平台管理员前往令牌管理。签发本身不授予项目成员权限；成员用个人令牌登录后只能访问已有授权的项目。

明文只存在于首次响应、签发弹窗短期内存及用户主动复制的剪贴板中，不写入 URL、日志、浏览器持久存储或服务端明文文件。相关 HTTP 响应设置 no-store，弹窗关闭时清空状态。令牌不自动放入管理员的登录会话。

## 服务端与存储

保持浏览器 HTTP → Node BFF → TS SDK → gRPC → Application 的路径。补充列举、签发、撤销、重新签发的协议和四语言 SDK 方法；HTTP/CLI 使用同一 Application 操作。权限判断、参数校验和审计由 Application 实施，SQL 仅位于存储适配器。

使用密码学安全随机源生成至少 256 位随机令牌，保存 SHA-256 摘要及不可变令牌 ID、subject、创建/到期/撤销时间、标签和签发者。SQLite/PostGIS 实现相同语义。受管令牌认证通过 Application 的存储语义操作查询，默认不做正向认证缓存，以便多实例在撤销事务提交后拒绝后续认证。存储故障应拒绝认证并返回服务错误，不能绕过受管令牌检查。

受管令牌采用独立前缀，避免与运维文件令牌的认证路径混淆；不能在受管认证失败后回退接受同一令牌的文件副本。已通过认证的在途请求允许结束；下一次服务调用会拒绝撤销令牌，BFF 收到未认证后清除对应会话。长流在开始时认证，文档明确在途请求的边界。

签发、撤销、重新签发及其全局管理审计原子提交。审计只记录令牌 ID、操作者、目标 subject、标签和生命周期变化，不含明文或摘要。令牌是全局身份资源，不能挂到一个项目的审计记录中。

## 一次展示与失败恢复

签发/重新签发接受唯一 request_id，事务中保存操作回执和参数指纹，不保存明文。相同 ID、相同参数的重试只返回已完成状态和令牌 ID，不重复签发、不再次返回明文；参数不一致拒绝。首次响应丢失时，界面提示令牌已签发但明文不可恢复，让管理员撤销该 ID 后重新签发。不得在前端自动换 request_id 重试签发。重新签发旧令牌时锁定并检查其状态，防止并发生成多个替代令牌。

## 数据格式与部署

新增全局受管凭据、操作回执和审计表属于结构变更，遵循仓库约定将格式从 11 提升为 12，并新建数据库，不实现旧格式自动升级。现有本地数据库不能直接用新二进制启动；实施验证使用隔离的新格式数据库。当前运行数据和服务不自动删除或切换，切换前明确告知用户。

原生备份包含凭据摘要和全局审计，恢复后保留凭据生命周期；备份的访问权限等同数据库。恢复早于撤销的备份可能复活令牌，恢复流程要求在对外服务前执行凭据轮换/撤销。现有项目逻辑导入导出不应携带全局身份凭据，格式文档需明确其边界。

## 验收

1. 非平台管理员即使是项目所有者也不能签发、列举、撤销或重新签发；不能为平台管理员身份签发。
2. 新令牌能够登录，不能访问未授权项目；授予角色后只能执行对应操作。
3. 列表、审计、重试、错误、日志及备份均不含令牌明文。
4. 撤销后原有 Web 会话的下一次后端请求被拒绝；重签后新令牌有效、旧令牌无效。
5. SQLite/PostGIS 覆盖事务回滚、跨实例撤销、并发重签、响应丢失、过期、数据库重启和备份恢复。
6. 四语言 SDK 生成与检查、./scripts/check.sh、Web 测试/类型检查/格式检查/生产构建通过；隔离数据库下验证真实浏览器签发→保存→授权→登录→撤销→重新登录失败→重签登录成功。

不包含用户名密码、邮件邀请、用户自助找回或 SSO 接入。

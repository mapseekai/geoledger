## 安全边界

镜像扫描器失败、报告缺少系统包清单、缺少预期原生库、架构不全、扫描报告或 blob 被改动、来源 SHA 不一致或凭据超过 24 小时，均拒绝发布。扫描不通过时也保存诊断报告。没有配置全局漏洞豁免，不能通过 `.trivyignore` 或继承的过滤环境变量绕过门禁。

构建 job 只有读取权限；通过扫描的 OCI 布局作为短期 artifact 交给发布 job。发布 job 再校验 blob 和扫描凭据，使用 `skopeo copy --all --preserve-digests`，核对最终 registry digest 并签名。生产标签不在构建阶段推送。镜像复审只拉取 Release 清单中的 digest，不扫描可能已经变动的浮动标签。

Windows 安装器不修改注册表、不安装全局运行时、不执行下载包中的脚本、不覆盖已有目录。Release 提供安装器及依赖锁文件，由操作方独立下载原生组件并保留上游许可证和源码来源信息。

## 本次续修与证据边界（2026-10-10）

发布扫描同时核对镜像的源提交标签、准确配置 digest、架构、镜像类别和报告哈希；服务器报告必须含 Rust 依赖与原生系统包清单。运行镜像不能伪装成 attestation 被跳过。门禁测试覆盖错误镜像、错误源 SHA、跳过质量任务、忽略扫描失败和提前推送。失败、过期或缺失的扫描凭据不会触发 registry 写入。

原生生命周期保护使用允许已有查询继续执行的共享锁：新连接初始化与析构仍独占，但等待析构不能把尚需提交或回滚的 SQLite 事务堵住。新增受控等待测试与 12 线程原生连接测试；本机 8 线程并行的一致性套件 26 项通过。该行为不要求降低测试并行度，也没有通过放宽操作期限掩盖问题。

四语言在线依赖门禁与 Go race 测试通过。基础镜像的原生／系统漏洞扫描是独立检查：已固定的 Node bookworm 基础镜像报告含 HIGH/CRITICAL 包-公告命中，诊断用 trixie 基础镜像同样仍有阻断项，因此本轮没有用仅更换发行版或扩大忽略列表制造通过结果。基础镜像诊断不等同于最终 GeoLedger 镜像的验收报告。当前发布流程继续对实际构建的双架构镜像执行严格阻断。

本机为 macOS，Windows DLL 的实际加载和 GitHub 多架构发布属于远端 CI 验收。安装包的校验与解包测试不冒充 Windows 执行通过；脚本与离线门禁测试通过也不冒充正式镜像已经通过扫描或已经发布。


续修新增跨数据库锁等待回归：只有 `BEGIN IMMEDIATE` 的锁获取阶段可按剩余期限重试；等待期间释放原生访问许可，写入与提交语句保持不自动重放，锁等待耗尽保留原有 `busy` 契约。服务端四项限流／超时测试连续四轮并行通过。

控制台运行镜像采用固定 digest 的 distroless Node 22（Debian 13），保留非 root、standalone 与本地静态资源，移除运行期不需要的 npm、shell 和发行版工具。Compose 探针使用绝对 Node 路径。该阶段验收时，构建阶段仍为完整 Node 镜像；后续已经改为独立精简工具链并重建原生 TypeScript，当前配置见 [构建环境修复记录](build-environment-fixes.md)。两阶段角色不同。

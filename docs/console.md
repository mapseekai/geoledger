# 管理控制台

GeoLedger 的管理界面内置在 `geoledger-server` 中，无需单独部署前端。
浏览器访问服务的 HTTP 地址后先进入登录页，输入管理员分配的访问令牌。
静态令牌和服务配置接受的 JWT 均通过现有 Bearer 认证流程验证。

令牌仅存在当前页面中，不写入 Cookie、localStorage 或 sessionStorage。
刷新页面需重新登录；退出或收到 HTTP 401 时清空令牌、资源结果和工作上下文，并关闭弹窗。
登录页不创建用户，也不设置数据库连接。用户身份和存储配置由服务管理员管理。

## 常用流程

1. 在 **项目** 中创建项目，或通过顶部选择已有项目。
2. 在 **数据集** 中创建数据集，点击名称进入要素列表。
3. 在 **工作区** 中创建个人草稿，点击「使用工作区」。
4. 进入数据集，点击「保存要素」，填写要素 ID 和 GeoJSON Feature。
   缺少 GeoJSON `id` 时由表单补齐；已有 `id` 必须与要素 ID 一致。
   相同 ID 更新已有要素，输入 `null` 在草稿中删除要素。
5. 查看「工作区草稿」和「草稿差异」，填写发布说明并确认发布。
6. 在 **发布历史** 中查看正式版本及变更明细。

表格每页 20 条，筛选只作用于当前页。正式要素翻页固定在同一正式版本，
刷新后读取最新版本；草稿在翻页期间改变时提示重新刷新。
工作区列表只展示当前身份的工作区。顶部项目选择器显示前 100 个项目，
更多项目可在 **项目** 页面分页进入。

**访问管理** 与 **审计日志** 仅供项目所有者使用；查看者无法创建数据集、编辑或发布。
权限始终由后端校验。访问管理按身份标识设置角色，当前没有成员目录或创建令牌功能。

## 高级操作与失败恢复

**API 工具** 提供全部现有 HTTP 操作，包括冲突查询、解决冲突、更新基线、
丢弃草稿以及生成撤销草稿。原始 JSON 请求与响应按文本保留，避免大整数数值丢失。
常规保存要素也保持 GeoJSON 原始数值，详情展示原始响应。

发布结果因断网等原因不确定时，发布对话框保留原请求并锁定发布说明，
再次提交会使用相同请求 ID 和完整请求体。也可在 API 工具中重试该原始请求。
发生版本冲突时，检查差异并通过 API 工具解决冲突，再进行发布。

## 视觉与静态资源

标志使用几何 G 与下层折线，表达空间数据及版本层次。青绿色为主色，
深色侧栏组织导航，浅色内容区域承载表格与表单。登录页与控制台共用标志。
布局支持窄屏导航、键盘表单操作、加载状态、空列表及错误提示。

[Logo](../crates/server/web/logo.png) 与页面随服务二进制嵌入，无外部字体、图标库或 CDN 请求。
HTTP `/logo.png` 提供标志，CSP 仅允许同源图片和 API 连接。

# 管理控制台

管理界面是独立的 [web 项目](../web/README.md)，使用 Next.js、React、TypeScript、
Tailwind CSS v4 和 shadcn/ui。`geoledger-server` 只提供业务与监控服务。
浏览器通过 HTTP 访问 Next.js，Next.js 服务端通过 TS SDK 连接 GeoLedger gRPC。

## 启动与登录

按 [Web 启动说明](../web/README.md#本地启动) 配置后，启动服务和 Web 两个进程。
默认浏览器地址 `http://localhost:3000`，业务服务 gRPC 地址 `http://127.0.0.1:7882`。
使用管理员分配的静态令牌或服务认可的 JWT 登录（控制台限制 2000 个 ASCII 字符）。数据库、用户身份和令牌由管理员管理。

令牌仅保存在经过加密与签名的 HttpOnly Cookie 中，不写入 localStorage/sessionStorage；
会话 8 小时到期，HTTPS 配置启用 Secure。每次调用仍由业务服务核验身份和权限。
所有浏览器写请求检查固定 Origin。页面、接口响应禁止缓存，页面使用 nonce CSP。

## 常用流程

1. 在 **项目** 创建或选择项目。
2. 在 **数据集** 创建数据集，进入要素列表。
3. 新建工作区，或选择已有工作区。下拉列表显示前 100 个工作区，
   「选择其他工作区」可按完整标识加载。
4. 添加或编辑 GeoJSON Feature；填写要素标识。缺少 `id` 时自动补齐，
   已有 `id` 必须与标识一致。删除使用独立的确认操作。
5. 填写版本说明，发布工作区。工作区页面可查看变更、冲突、解决冲突、更新基准和丢弃草稿。
6. 在 **版本历史** 查看提交详情，或撤销指定版本的更改：先创建反向编辑工作区，再检查、发布。
   撤销某次提交保留其他版本的变化，不等于恢复整个历史快照。

列表每页 20 条，项目筛选只作用于当前页。已发布要素翻页固定在同一版本；
刷新后读取最新版本。工作区在翻页中被修改时会提示刷新，避免混合不同草稿版本。
GeoJSON 原始数字在读取、展示、编辑与保存中保持精度，包括 64 位整数。

权限始终由业务服务检查。成员权限按身份设置为 owner/editor/viewer；
控制台提供权限设置和审计查询，不生成令牌或虚构成员目录。

## 发布失败恢复

首次发布前，浏览器保存不可变的发布意图；网络中断或响应超时后，重试使用
完全相同的请求标识、工作区版本和说明。刷新或登录过期也保留此意图。
在工作区页面点击「重试原发布」，可确认已经提交但响应丢失的请求。
待确认时禁止同一流程继续编辑；服务端仍使用乐观版本检查并拒绝冲突。
主动退出会清除本标签页的发布意图，退出前请先确认结果。

## 设计与验证

设计依据 [Mistral DESIGN.md](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/mistral.ai/DESIGN.md)，
使用暖白、奶油色、橙色强调、细边框、页底日落色带。[GeoLedger 矢量标志](../web/public/logo.svg) 使用 G 与叠层轮廓；登录页、导航及浏览器图标共用 SVG，按比例完整显示。
字体与图标随 Web 打包，运行时无外部 CDN 请求；桌面与手机均可使用。
字体授权与替代说明见 [Web 项目文档](../web/README.md#设计来源)。

真实浏览器回归 [test-console.py](../scripts/test-console.py) 覆盖登录、Cookie、CSRF、
创建/编辑/发布、精确数字、发布响应丢失后的刷新重试、分页、历史撤销、权限、审计、退出和手机布局。
脚本会创建测试数据，仅对隔离测试服务运行。

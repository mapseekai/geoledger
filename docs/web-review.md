# 独立 Web 控制台验证记录

本轮将管理界面从 Rust 二进制中移出，形成可独立构建和部署的 `web/` 项目。
Next.js 服务端调用 Node.js TS SDK，浏览器只使用同源 HTTP。
数据库、版本事务、权限与业务逻辑仍由 GeoLedger 服务统一处理。

## 审查与修正

独立审查覆盖浏览器状态、请求边界、认证、部署产物与现有业务契约。
已修正并复核：

- 历史操作准确描述为“撤销指定版本更改”，保留其他版本的变化。
- 成员页面提供按身份设置 owner/editor/viewer 权限的操作，项目列表展示服务返回的项目信息。
- 工作区选择器支持按完整标识加载，超过首 100 个时仍能编辑。
- 发布意图跨断线、刷新与会话过期保持不变；既有未知请求遇到身份失败仍保留，
  明确业务冲突则释放，以便解决冲突。写入重试由用户明确发起。
- 256 字节和带前后空格的现存要素标识保持可编辑；GeoJSON 数字保持精度。
- 要素、变更与冲突翻页检查相应版本；附属版本状态由当前有效请求更新。
- 控制台的 2000 字符令牌上限、8 小时会话期限与主动退出清理行为已说明。
- TS SDK 的 `@grpc/grpc-js` 更新至 1.14.5；Web/SDK 运行依赖通过当次安全审计。

审查修正已复核，目标部署环境通过专项验收确认运行表现。

## 实测范围

- Web 单元测试 7 项、TS SDK 单元测试 7 项，类型检查与格式检查通过。
- Next.js 生产构建、standalone 登录/静态资源/真实 SDK 调用通过。
- 最终 Docker 镜像以非 root、只读文件系统运行，同一完整 Chromium 回归通过。
- Chromium 完整流程通过：登录失败与成功、HttpOnly/SameSite Cookie、Origin 拒绝、
  项目/数据集/要素编辑、精确 uint64、发布响应丢失后刷新并重新登录重试、
  历史撤销、权限设置、审计分页、主动退出与手机布局。
- 浏览器边界流程通过：第 101 个工作区按标识编辑，256 字节含空格 ID 保存，
  草稿变化后提示重新读取，保持分页版本一致，正式版本在其他用户发布后仍固定原快照翻页。
- 后端 `scripts/check.sh` 通过，含 fmt、Clippy、文档链接，以及 43 次 Rust 测试执行，
  覆盖 SQLite/PostGIS 的相同一致性套件、真实服务和存储约束。

这轮验证覆盖上述 Web 构建、部署与浏览器流程。百万要素/20 人容量基线见
[生产验证记录](production-review.md)；Web 的实际吞吐和代理配置通过目标环境验收确认。
构建与检查命令见 [开发说明](development.md) 和 [Web 文档](../web/README.md)。
